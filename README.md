# doc
这几个概念在业界文档里经常混着用，但严格定义下它们是有清晰区分的——区分的关键在于路口的物理形态、功能角色、以及对驾驶动作的语义要求。下面按"是什么 / 看什么 / 为什么单独处理"三个维度来讲。

一、按维度对比总览
类型	几何特征	功能角色	典型驾驶动作	播报特点
普通路口 (Intersection)	多条边在一点相交，明显角度差	路网节点，多路汇集	左转/右转/直行/掉头	"左转 / 右转 / 直行"
Fork（分叉）	一条路在前方分成 2~3 条，角度差小	同一道路在物理上分裂	靠某一侧继续行驶	"靠左/靠右行驶"
Bifurcation（分歧）	Fork 的子集，强调"主路一分为二"	主路终结点，两条都是新主路	选择其中一条作为新主路	"靠左走 X 路 / 靠右走 Y 路"
Motorway link（匝道）	短连接段，单向，连接主线与其他道路	进/出高速、立交转换	进入匝道 / 离开匝道	"驶入 X 出口 / 上 X 高速"
Roundabout（环岛）	单向闭环 + 多个进出口	用环行替代信号灯交叉	进入环岛 → 第 N 出口驶出	"进入环岛，从第 N 个出口驶出"
Internal（内部边）	路口内部的短连接边	路口内部细节，非真正的路段	不应作为独立 maneuver	不播报（合并）
下面分别展开。

二、Intersection（普通路口）
定义：两条或更多道路在一个节点相交，分支之间存在明显角度差（一般 ≥ 45°）。

几何特征：

节点处入边与各出边的转角分布广（典型十字路口：0°/90°/180°/270°）
通常有交通信号或停车标志
物理上是"汇集点"，不是"延续点"
判定要点：

出边夹角足够大，没有明显"主路延续"的方向
出边的道路等级、name 通常各不相同
不属于 fork / link / roundabout / internal
驾驶语义：用户做的是离散选择——左转、右转、直行、掉头。所以播报使用 turn 系列动词。

业界为什么单独处理：因为这是最常见、最规则的形态，规则集相对简单：用角度 + 出边数量基本就能判完。其它形态都是从这个 baseline 偏离出来的特殊情况。

三、Fork（分叉）
定义：一条道路在前方分成两条（极少数情况三条），且所有分支彼此夹角小、几乎平行。

几何特征：

入边只有 1 条
出边 2~3 条
出边之间夹角小（一般 < 45°，常常 < 30°）
没有任何一条出边明显是"转弯"
典型场景：

高速公路在前方一分为二（不一定是主辅分流）
城市快速路 Y 形分叉
主路前方变成两条独立的路
判定要点：

出边数 = 2 或 3
所有出边都属于"near-straight"（与入边夹角小）
出边的功能等级接近（这是与 motorway link 的关键区别）
驾驶语义：用户面对的是连续选择——不是"转弯"，而是"沿哪一边继续走"。所以播报使用 keep 系列。

业界为什么单独处理：

用普通路口的规则会判成 "slight left / slight right"，但用户不会觉得自己在"转弯"
角度信号很弱，必须靠拓扑形态本身触发 keep 语义
国家/地区差异大：欧美高速 fork 很常见，需要特别明确的话术
四、Bifurcation（分歧）
定义：Fork 的一种特殊子集——主路在此终结，两条出边都是新的主路。"分歧"强调的是"主路一分为二"，不是"主路 + 岔路"。

几何特征：

入边 1 条，出边 2 条
两条出边都是高等级路、都有新的 name / ref
入边的 name / ref 通常不延续到任何一条出边（或者只延续到其中一条但另一条同等重要）
与 Fork 的区别：

普通 fork 可能是"主路 + 出口匝道"（主路是延续，匝道是偏离）
Bifurcation 是"主路结束，两条都是新主路"，没有"延续"概念
典型场景：

美国 I-95 在某点分成 I-95 North 和 I-495（两条都是州际公路）
中国 G15 沈海高速在某点分成两条不同编号的高速
城市主路在前方分成两条同等级城市快速路
判定要点：

是 fork 的形态
两条出边等级 ≥ 入边等级，且 name / ref 都不延续
配合 sign post 信息（一般有大型分歧指引牌）
驾驶语义：必须明确告知"靠左走 A，靠右走 B"，因为用户没有"延续主路"这个 default 选择。话术比普通 fork 更强：

Fork: "Keep right"
Bifurcation: "Keep right to take I-95 North toward Boston"
业界为什么单独处理：

用户在 bifurcation 处犯错的代价非常高（走错可能要开几十公里才能掉头）
需要强制带 destination 信息播报
提前通告距离更长（一般 2~3 km 就开始预播）
五、Motorway link（匝道 / 连接段）
定义：连接主线与其他道路（另一条主线、地面道路、服务区等）的短单向道路。在 OSM 里就是 motorway_link、trunk_link、primary_link 等 tag。

几何特征：

单向
道路等级标记为 link（比主线低一级，但承担连接功能）
长度通常较短（几十米到几百米）
一端连主线，另一端连其他道路或环岛
两种使用场景：

离开主线（Exit ramp）：从主线 → link → 其他道路
进入主线（Entry ramp）：从其他道路 → link → 主线
与 Fork 的区别：

Fork 的所有出边等级接近；motorway link 是"主线 + 匝道"，等级有明显落差
Fork 的出边都可能是新主路；motorway link 的 link 边只是"过渡边"，本身不是目的地
判定要点：

出边里有一条是 link 类型，另一条是主线
入边和"主线那条出边"通常 name 延续
驾驶语义：

不是"keep"也不是"slight turn"，而是"take exit / merge onto"
通常配合 exit number 和 destination 播报："Take exit 23 toward Springfield"
业界为什么单独处理：

link 边在路网里是结构性特殊边，不能当普通边处理
进/出主线的话术完全不同，不能混用 fork / turn
长 link（盘旋立交）需要把多个连续 link 合并成一个 maneuver
短 link（不到 30m）经常需要忽略，否则会出现"上匝道 → 立刻右转"这种碎播报
六、Roundabout（环岛）
定义：单向闭环道路 + 多个进出口构成的特殊路口形式。

几何特征：

一组首尾相连的边构成闭环
在 OSM 里 tag 为 junction=roundabout 或 mini_roundabout
闭环上有多个分支边（进入和驶出的连接）
关键属性：

必须按"第 N 出口"播报，不能按角度
顺/逆时针方向取决于左舵/右舵国家（右舵国家如英国、澳大利亚是顺时针）
有"进入"和"驶出"两个独立的 maneuver 概念
判定要点：

当前边的下一节点是 roundabout 节点
路径会沿闭环走一段，再从某条出边驶出
需要计数从入口到出口之间经过了几个分支
驾驶语义：完全独立的播报模式：

进入："进入环岛，从第 3 个出口驶出"
接近出口："从下一出口驶出"
驶出（隐式）
特殊变体：

Mini-roundabout：直径很小（一般 < 10m），常常画成中心圆点。语义上仍是环岛，但有时按普通路口处理
Magic roundabout / 复合环岛：英国常见的多环复合，非常难处理，多数引擎降级为多个普通路口
业界为什么单独处理：

几何上是闭环，普通"角度判转向"完全失效
全球 90% 的导航引擎都把 roundabout 作为独立的 maneuver 类型，话术、UI 图标、提前距离都是单独的一套
出口计数逻辑很特殊（要沿闭环遍历）
七、Internal edge（内部边 / 路口内部边）
定义：路口物理范围内部的短连接边——它们在地图数据里被建模成独立的边，但语义上不是真正的"道路段"，而是路口的内部结构。

几何特征：

长度很短（一般 < 25m，有的引擎用 < 50m）
两端节点都是同一个路口的不同分支起点
道路名通常缺失或与主路不一致
OSM 里典型例子：复杂十字路口被画成"四段短边围成的小四边形"
典型场景：

大型十字路口被建模成内部多边形（避免左转线穿过对向车道）
立交内部的连接段
高速服务区内部的微观路网
判定要点：

边长 < 阈值
两端节点的"路口邻接性"很强（属于同一个 logical intersection）
通常配合启发式：从主路下来→走 internal→上另一条主路，整段被识别为"在大路口内"
驾驶语义：不应该播报。Internal edge 上不应该产生 maneuver；应该把跨越 internal edge 的多个动作合并为一个外部 maneuver。

业界为什么单独处理：

不识别 internal 会出现"左转 → 5 米后再左转 → 10 米后右转"这种荒诞播报
Valhalla 和 OSRM 都把 internal intersection detection 作为独立的预处理阶段
商用引擎一般在 map compile 阶段就把 internal 标好，运行时直接跳过
八、几个容易混的辨析
Fork vs Bifurcation
形态都是"一条变两条"
Fork = 通用形态描述（角度小、近平行）
Bifurcation = 强语义描述（主路终结、两边都是新主路）
Bifurcation ⊂ Fork，但话术更强、提前播报更早
Fork vs Motorway link exit
形态有时长得像（都是"主线变两条"）
Fork：两条出边等级接近，没有"主辅"概念
Motorway link exit：一条主线 + 一条 link 匝道，有明显的"主辅"层次
关键判据：出边的 highway / functional class 是否相同
Intersection vs Fork
Intersection：角度差大（≥ 45°），是"汇集点"
Fork：角度差小（< 45°），是"延续 + 分裂"
不靠角度，仅看节点出度无法区分（都可能 ≥ 3 个分支）
Roundabout vs 普通圆弧路口
Roundabout：单向闭环 + 多分支
普通圆弧：可能是双向、不闭环、或闭环但没多分支
判据：tag + 单向性 + 闭环性三者同时满足
Internal vs 短边
不是所有短边都是 internal
Internal：在 logical intersection 内部
普通短边：可能就是真的有一段很短的路（比如老城区窄巷）
判据：边长 + 上下文（两端是否属于同一个路口）
九、为什么要做这套分类
回到第一性原理：用户的认知模型里没有"角度"，只有"路口长什么样"。

站在 fork 前，用户看到的是"前面路分叉了"，不是"路转了 25°"
站在 bifurcation 前，用户看到的是"两条主路都行，得选一条"
站在 motorway link 前，用户看到的是"那是个出口"
站在 roundabout 前，用户看到的是"我得绕一圈再出来"
把这些形态识别清楚后，每种形态有专属的话术、提前距离、UI 图标、置信度阈值。一旦把形态错判（比如把 motorway link 当成 fork），话术就会"听起来很奇怪"，用户体验立刻崩掉。

一句话总结
这五类（加上 internal 共六类）不是按角度切的，是按路口的物理形态 + 功能角色 + 用户认知模型切的。识别它们的过程是路径规划完成后、生成 maneuver 之前的核心预处理步骤；分类做对了，后面的 keep / slight / turn 判定才有意义。Valhalla 的 maneuvers_builder.cc（你正打开的这个文件的兄弟文件）和 OSRM 的 guidance module 都是这套范式的开源参考实现，可以对照着看。
